## Follow-up observations later on 2026-10-19 (basis for v0.1.104)

Same session and capture type (reduced sketches). Gemini selections were changed to read the menus and then restored to `Flash-Lite` + `최저가`.

### Gemini thinking level and pill

- The thinking submenu items are `gem-menu-item` rows with a title line and a description line. The selected one has class `selected` and a check icon.
- The level is global: switching between Flash-Lite, Flash, Pro and Argon kept the chosen level.
- The pill `button[data-test-id=bard-mode-menu-button]` contains `[data-test-id=logo-pill-label-container]` with `.picker-primary-text` (model short name: `Flash-Lite`, `Flash`, `Pro`, `Argon`) and a secondary text for the level (`보통`, `최고가`). For `최저가` no secondary text is shown.
- aria-label example: `모드 선택 도구 열기, 현재 Argon 보통 모드 사용 중`.

### YouTube transcript request

YouTube's own transcript panel loads through:

```text
POST https://www.youtube.com/youtubei/v1/get_panel?prettyPrint=false
body: { context: { client: { clientName: "WEB", clientVersion, hl, gl } },
        panelId: "PAmodern_transcript_view", params }
params = base64( 0xaa 0x09 <len> | 0x0a 0x0b <11-byte videoId> 0x18 0x01 )
```

- A minimal context (no cookies needed beyond the page's own) returned segments for `jNQXAC9IVRw` and also for `ITFtxbK-n-A`, whose native panel stays on a spinner.
- Response segments are `transcriptSegmentViewModel` objects with `simpleText` and `timestamp`.
- The response body arrived gzip-compressed when captured through a fetch hook; the page's own `response.json()` handles it normally.

### What v0.1.104 changed from these observations

- ChatGPT: new composer, trigger and send selectors. The model is never changed; only the effort is set and the checked model must be the same before and after.
- Gemini: models `3.5 Flash-Lite`, `3.8 Flash`, `3.1 Pro`, `4 Argon`; levels `최저가`, `보통`, `최고가`; selection confirmed from the pill's primary and secondary text.
- YouTube: `get_panel` is tried first, before the older caption-track paths and the DOM fallback.

## Live send check with v0.1.107 (2026-10-19, same video): root cause

- Text trace: `[{"t":45245,"event":"send-button-missing","buttons":[]},{"t":48257,"event":"enter-outcome","outcome":"not-sent"}]`.
- The page then had exactly one editor (`div.ProseMirror` in `form [data-composer-input]`, holding the prompt) and the normal `보내기` submit button.
- So the editor the extension injected into had been replaced by a re-render, and searching from the detached editor found no buttons. v0.1.108 follows the live composer.
- Tool note: Claude in Chrome `read_console_messages` sometimes returns nothing on a later call for the same tab; the final one-line trace is the reliable record.

## Live send check with v0.1.108 (2026-10-19, same video)

- Trace: `[{"t":45025,"event":"send-button-missing","inputConnected":false,"buttons":[]}]`, so the injected editor was again detached, and the live-composer lookup also found nothing.
- The tab had `innerWidth = innerHeight = 0`: it was opened, then the tool acted on the YouTube tab, so the new tab was never shown. The editor measured width 0 (height about 91k px) and the size-based visibility check rejected it.
- Earlier page-context clicks still sent in such tabs, so ChatGPT itself accepts the send. v0.1.109 makes visibility style-based when the viewport is 0x0.
- Testing note: after clicking Summarize, act only on the new provider tab so it gets shown, unless testing the background case on purpose.
